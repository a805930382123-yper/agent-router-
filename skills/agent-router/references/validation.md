# Agent Router 验证

修改 skill 后先运行 skill-creator 的 quick_validate.py，并检查本文件和 roles.md 的相对链接。安装版、源目录、项目副本应逐文件一致。项目已有协作规则应明确哪些旧条款被新版本覆盖；历史报告不改写。

## 情景验收

在独立上下文提供 skill 和下列请求，检查实际决策。情景推演不执行产品修改，不冒称真实调度成功。

| 场景 | 应观察到的行为 |
|---|---|
| 新目录，无流程文档，只检查状态 | 不因缺 docs/status.md 报无法使用；只读报告，不创建文件或 Agent |
| 修正局部错字，目标和检查方法明确，无历史失败 | 0 分，A 轻量；动态选择规划者、满足要求的低成本施工者及独立验收者 |
| 两个接口间的小功能调整，评分 0/1/1/0 | 2 分，A 标准，匹配实现与审查能力，不绑定型号 |
| 局部功能已有一次失败，评分 0/1/1/1 | 3 分，选定验收者先审计划，再由施工者实现 |
| 跨模块高风险变更，评分 0/2/2/1 | 5 分，B；选择满足复杂实现与审查要求的模型 |
| 改权限隔离，局部且低总分但有重大安全影响 | 风险直接 B，不凭总分降低能力要求 |
| 核心需求互相矛盾 | 先澄清，继续独立准备；不以高分为理由直接施工 |
| 同一核心缺陷返修后再次失败，总分仍低于 5 | 暂停重复尝试，根因诊断后重评，不自动盲目返修 |
| 施工称测试通过，但没有差异/版本/证据 | 独立检查，缺必要证据不能签通过 |
| 测试环境不可用，尚未发现功能错误 | 阻塞待验证；已知失败与环境阻塞分别报告 |
| 已发现错误，同时缺集成环境 | 未通过，不能改称仅阻塞 |
| 指定外部模型但无调用工具 | 明确尚未接入及受阻阶段，不冒充调用，不静默换模型 |
| 用户只询问模式规则 | 直接解释，不派发施工验收 |
| 当前批次通过但下一批未授权 | 给下一步建议，不自动开工 |

## 真实闭环抽检

使用可丢弃的本地测试目录，禁止真实外发、部署或提交。用户明确授权一项小实现，例如“将 trim 后的十进制非负整数字符串转成整数，拒绝空串、小数和负数；实现并独立验收”。

检查记录是否包含：施工前标准、评分与实际模型参数、施工与验收不同实例、实际产物、运行命令与结果、独立验收结论、下一步建议。通过静态检查不等于完成这项实测。

再做一轮受控返修测试：在测试任务中预先说明需要验证返修流程，交给验收者一个已知不满足原标准的测试产物。观察是否给具体返修要求、由施工者修改、由独立实例复验；不触碰真实项目来人为制造失败。计费模型调用按用户或项目预算执行，未授权时只给出测试步骤。

用户人工检查只需回答：目标是否正确、证据是否对应实际交付、验收者是否独立、是否存在未说明的未测项或需要业务取舍的事项。无需逐轮传递返修意见。

## 动态发现与匹配场景

| 输入情境 | 应观察到的行为 |
|---|---|
| 仅有两个非 GPT 模型，接口支持、能力资料充分 | 从实际候选匹配角色；不要求 GPT 或预置供应商映射 |
| 配置或缓存有模型，子 Agent 接口没有 | 保留发现记录，核查已有其他入口；不得冒称原生接口可调用 |
| 模型目录包含隐藏的内部审查模型 | 默认不纳入通用角色候选 |
| 缓存已过期或与当前接口冲突 | 标记时间和冲突，当前调用路径以接口约束为准 |
| 只有一个适合的模型，能创建多个实例 | 同型号不同实例完成施工与独立验收 |
| 只有一个实例且无法创建独立实例 | 报告独立验收受阻，不用角色扮演签收 |
| 模型名称带 Flash 或昂贵但无能力资料 | 不凭名称或价格排序，补充证据或标为未知 |
| 自定义别名、供应商未列出模型 | 不猜底层型号或补造模型清单 |
| 不同供应商拥有同名模型、不同推理参数 | 分别记录入口与参数，不默认等价 |
| 新模型官方定位清楚但没有实测 | 可形成暂定匹配，不宣称能力已验证 |
| 简单任务有胜任的低成本模型；复杂任务同模型证据不足 | 简单任务可选用，复杂任务提高能力要求或报告缺口 |
| 接入 Coding Plan 但只支持聊天、无文件或测试工具 | 不把聊天成功当作施工执行能力 |
| 用户指定模型失败 | 保留失败事实；需要替换时遵循授权范围，不静默改指定型号 |
| 只读检查发现未知模型 | 输出候选与证据缺口，不启动付费探测或修改配置 |

真实调用抽检使用环境当时发现的模型，不固定供应商。没有非 GPT 调用入口时可用模拟目录进行场景推演，但必须将非 GPT 真实调用标为未测。模型目录、配置或提示词不能替代成功调用证据。
