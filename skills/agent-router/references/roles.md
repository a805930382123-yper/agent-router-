# 角色模型配置

默认预设面向支持下列模型的 Codex 宿主。可用性以当次工具暴露和实际创建结果为准，不依赖产品显示名称猜测 API 标识。

| 配置键 | 默认模型标识 | 推理强度 | 用途 |
|---|---|---|---|
| planner | `gpt-6-astra` | `medium` | 所有模式的规划、标准与重大取舍 |
| builder_light | `gpt-6-luna` | `high` | A 轻量施工 |
| builder_standard | `gpt-6.1-terra` | `high` | A 标准施工 |
| builder_high | `gpt-6.1-sol` | `high` | B 施工 |
| reviewer_standard | `gpt-6.1-sol` | `high` | A 独立验收、3–4 分先审计划 |
| reviewer_high | `gpt-6-astra` | `medium` | B 独立验收 |
| diagnostician | `gpt-6.1-sol` | `high` | 重复核心失败的根因诊断 |

Astra Medium 是本预设的默认值，不覆盖用户已明确选择的其他受支持强度。没有明确配置时采用本表；指定强度不可用时报告，不自行改值。

## 替换模型或接入其他供应商

在项目已有协作文档中记录角色映射即可，无需专门创建配置解析器。配置需包含：角色键、供应商/执行工具、真实模型标识、支持的推理参数（无此参数写“不适用”）、必要能力和调用验证状态。明确适用项目或批次；不要把一个项目的替换写成全局默认。

映射选择以用户当前指定、项目明确配置、此默认预设的顺序确定；出现无法解释的冲突先指出受影响操作。更换映射不改变验收标准，不承诺不同供应商参数或模型能力等价。

外部模型必须通过当前可用且获授权的工具/API/CLI 调用，能够读取限定输入、交付产物和返回执行证据。没有对应工具、访问权限或凭据时，只能报告“尚未接入”，不能声明已经支持真实调用，也不为验证而暴露凭据或擅自配置账户。用户需明确批准替换，不能因默认模型失败自动切到别家。

配置记录和角色提示词不执行模型切换。通过真实调用参数指定模型；若宿主要求独立上下文才能选择模型，按该接口创建。协调者不得将其他任务聊天当作子 Agent，除非用户明确要求使用那些聊天。

## 交接最小信息

- 任务：目标、范围/排除项、验收项、必要背景、文件所有权、预算及停止条件。
- 施工交接：实际模型和 Agent 实例标识、变更文件、版本/指纹、已运行检查及结果、未完成项；交接后停写。
- 验收：验收实例与施工实例不同，实际模型、所验版本、原始标准、实际差异、实测/复用/未测证据、结论及返修要求。

可以通过现有任务卡和报告链接传递，不重复复制整份项目背景。只有可独立验证且所有权清楚的子任务才并行；不得为凑角色数量而重复派发。
