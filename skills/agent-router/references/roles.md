# 模型发现与角色匹配

默认不预设供应商、型号名单或品牌排名。用户明确指定优先于项目角色配置，其余角色从当前 Codex 环境动态选择。指定配置仍需核对真实调用能力。

## 发现当前模型

先检查当前会话的子 Agent 工具及其模型、推理参数和独立实例能力；这是该调用路径的直接约束。再按需读取有效 Codex 配置中的 model、model_provider、profiles、model_providers 和显式模型目录，解析与本项目有关的覆盖项。尊重实际 CODEX_HOME；未设置时使用用户目录下的 .codex。仅提取模型相关字段，不输出密钥、认证头或令牌，不读取凭据内容来枚举模型。

有可用的宿主模型枚举接口时优先查询；例如已接通的 app-server model/list。否则可读取 models_cache.json 作为补充，记录来源与更新时间。缓存和目录并非账户权限证明，不为只读发现启动推理、切换配置或创建聊天。没有枚举接口时报告发现范围，不声称枚举了账户全部模型。

按供应商、真实模型标识和调用入口区分候选；不同入口的同名模型不能自动合并。配置中的供应商不代表已知它的全部模型。隐藏或内部专用条目默认不作为通用角色候选。不要将一次发现的型号名单写成 skill 的固定白名单。

候选记录应区分：
- **已发现**：配置、目录或缓存中存在。
- **接口支持**：当前执行入口允许指定该模型及必要参数，但尚未证明请求成功。
- **调用已验证**：有对应入口、型号和时间的成功执行记录。只证明当时请求成功。
- **不可调用 / 待验证**：接口未暴露、访问失败或缺少执行证据，注明原因。

缓存存在但原生子 Agent 接口未暴露的模型，不得直接传入该接口。只在已配置且获授权的其他执行入口能指定模型、提供所需工具并创建独立实例时，才将其纳入该路径的候选。Coding Plan 是访问方式，不是能力等级；接入 Plan 不等于所有模型或所有客户端均可调用。不得为发现模型擅自安装客户端、配置账户或改写 Codex 设置。

## 根据证据判断角色适配

分别判断规划、实现、审查与诊断能力，不计算一个通用强弱总分。先核对角色需要的工具执行、上下文和模态等条件；模型 API 能聊天，不等于执行环境能编辑文件和运行测试。

结合匹配当前版本的任务记录、官方模型资料及宿主元数据形成初步判断，记录来源、时间、适用任务和置信度（充分 / 暂定 / 未知）。官方定位可支持暂定选择，不能当作实测结果；不凭型号后缀、价格、列表顺序、推理档位名称或模型自述判定优劣。自定义别名无法解析时保留未知，不猜底层模型。

未知模型先查可得资料；仍不足时，可在已授权执行范围和预算内用小型代表任务验证必要能力，或在首个低风险任务中形成证据，不为每次调度运行全套基准。只读检查不做推理探测。无法判断高风险任务所需能力时，明确受影响角色与缺口，继续独立准备工作；需要用户选择时给出具体选项。

## 按批次选择与执行

- 规划优先选择需求分解、接口推理能力较强的候选；验收优先选择审查、反例分析和验证能力较强的候选。
- 实现在达到本次能力要求的候选中，按已知成本、延迟及用户偏好选择。复杂实现同样可以使用能力较强的模型；没有成本数据时不要声称更便宜。
- 只有一个适合模型时可以承担多个角色，但施工和最终验收必须使用不同实例。独立实例不要求不同供应商或不同型号；无法创建独立实例时报告验收受阻。
- 推理强度采用该入口实际支持的参数，结合任务选择；无此参数写“不适用”。不同供应商的同名档位不视为能力等价。
- 默认动态选择无需逐次确认。用户指定型号不可用，或替换会跨越已授权供应商、数据范围、预算时，报告具体选项，不静默替换。已授权候选内的替换记录原因、更新角色映射，不改变验收标准。

每批记录角色、供应商/入口、真实型号、推理参数、选择依据和验证状态。通过工具真实参数执行；提示词与配置声明不等于已切换模型。调用失败不能记为角色完成，也不能仅凭调用失败判定模型能力低。

复用范围、版本与关键假设仍适用的能力证据。配置、调用入口或模型版本变化时重新核对受影响项；失败记录只影响有证据关联的任务能力，不一次失败全局降级。只读模式在聊天汇报，执行模式沿用项目任务记录，无需新增数据库、通用网关或全局排行榜。

## 交接最小信息

- 任务：目标、范围/排除项、验收项、必要背景、文件所有权、预算及停止条件。
- 施工：实际模型和实例标识、变更文件、版本/指纹、检查结果、未完成项；交接后停写。
- 验收：独立实例、实际模型、所验版本、原始标准、实际差异、实测/复用/未测证据、结论及返修要求。

通过现有任务卡和报告链接交接。只有可独立验证且所有权清楚的子任务才并行，不为凑角色数量重复派发。
