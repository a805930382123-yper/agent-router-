# Agent Router

让用户决定目标、范围和业务取舍，由 Agent 完成有证据的交付闭环。先区分本次是检查、咨询还是执行；调用本 skill 本身不扩大授权。遵守最新用户指令及适用项目约束。

## 入口与项目发现

- **状态检查 / 恢复进度**：只读核查并给建议，按下方预检执行。不派发 Agent、不修改记录、不启动服务或产品测试、不拉取、提交或推送。
- **咨询 / 方案建议**：直接提供分析；需要时给评分和协作建议，不强制施工与验收流程，不把建议当作开工授权。
- **实现 / 修复 / 产物交付**：用户已明确目标和范围时，进入规划→施工→独立验收→必要返修。授权沿会话持续有效，范围内可逆操作及必要本地验证连续推进。仅缺少会改变结果的信息时提问，继续不依赖答案的工作。

从当前项目根查找适用的 AGENTS.md 及其引用；按任务读取状态、当前任务卡、验收记录、架构或需求。已有文档结构优先，不强制要求 docs/status.md 等固定路径。缺失既有验收证据时报告缺口，不补造历史通过结论。

新项目或没有流程文档的项目，可以在首次已授权执行时建立一份简短任务记录，放入项目已有文档目录或用户指定位置，合并记录范围、标准、角色、验证与结论；简单任务也可在聊天中记录。只读检查不创建这些文件。预算、授权范围与历史结果沿用已有记录，不能因换模型或换批次重置。

## 角色与实际调用

流程以角色定义，默认模型及替换方式见 [角色配置](references/roles.md)。协调者负责发现规则、收集证据、调度和汇报；规划者制定方案与验收标准；施工者实现并自查；验收者对交付实物独立裁决。

执行前检查宿主工具实际支持的角色、模型标识、推理强度与调用接口。分别记录配置声明、工具暴露能力、实际创建结果；文档和提示词不等于模型已切换。当前聊天可承担其实际配置匹配的规划或验收角色，否则通过支持的子 Agent 工具派发。没有子 Agent 能力或指定模型不可调用时，说明受阻步骤和可选配置，等待用户决定替换，不静默降档或用角色扮演冒充实际模型。

**施工者与最终验收者必须是不同 Agent 实例。** 高档模式的规划者可兼任验收者，前提是未参与施工。验收者发现缺陷后交施工者修改，自己不改待验收产物；若已参与修改，应另选独立实例验收。新建指定模型子 Agent 时只传必要任务上下文与项目规则，使用工具真实模型/推理参数；固定角色配置不匹配时不得使用它冒充目标配置。

## 按当前批次评分

每项 0–2 分，列出分值和具体依据；不对整个项目永久定档。信息不足不能自动计为 0，应先调查或标明暂定值。

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 需求明确度 | 目标及验收标准清楚 | 有局部取舍待定 | 核心目标或标准不明确 |
| 模块耦合度 | 单点且边界独立 | 涉及少量接口 | 跨多模块或关键链路 |
| 变更风险 | 易回退、影响小 | 影响主要功能 | 涉及数据完整性、安全、权限或升级兼容性 |
| 历史失败 | 无相关失败 | 已出现一次有效失败 | 同类核心问题修复后再次失败 |

| 总分 / 模式 | 规划与验收标准 | 施工 | 独立验收 |
|---|---|---|---|
| 0–1 / A 轻量 | Astra | Luna High | Sol High |
| 2–4 / A 标准 | Astra | Terra High | Sol High |
| 5–8 / B | Astra | Sol High | Astra |

- **需求明确度为 2**：先澄清核心目标，不能靠提高模型档位继续依赖该答案的施工。
- **重大数据完整性、安全、权限或升级兼容风险**：直接 B，仍需清楚的标准和必要授权。
- **A 轻量**只用于目标清楚、修改局部、验证直接的任务。不满足时至少 A 标准，即使总分仅 0–1；不能为使用 Luna 而拆分或压低风险。
- **3–4 分的 A 标准**：Sol 先审计划及验收可执行性，再由 Terra 施工。
- **同一核心缺陷修复后再次失败**：暂停重复施工，先由 Sol 做有证据的根因诊断，再由规划者决定改方案、重新评分或升级。不得仅因总分较低继续盲试。

这些是初始调度规则，不是模型能力基准排名。项目明确约定的映射/阈值及用户指定模式可以覆盖默认值，必须说明差异。普通项目映射/阈值配置不取消核心需求澄清、重大风险直接 B、重复失败先诊断、真实能力核验和验收独立性。用户明确要求例外时说明与规则的差异及仍需满足的验收证据，遵守适用的更高层约束，不自行推断例外。复用已确认且范围、风险、关键假设未变的计划与标准；实质变化时重评，模式更新不修改历史 Agent 身份。

## 已授权执行闭环

1. **规划并冻结标准**：读取已有修改和当前任务。由规划者确定目标、必做/排除项、接口、文件所有权、验收项、验证方式和需用户判断的业务/视觉事项。标准必须在施工前确定；复用有效旧方案，不重复规划。计划明确且在已有授权内即可调度，无需为流程再索取一次开工确认。
2. **施工与自查**：给施工者任务卡、必要资料、验收标准和停止条件。明确共享工作区中还有其他工作，不覆盖他人修改。施工者实现、做必要检查及局部修复，交接变更文件、实际命令/操作及结果、版本或文件指纹、未完成项，随后停写。
3. **独立验收**：收到交接并确认停写后，验收者读取原始需求、冻结标准、实际交付差异和证据，独立检查关键行为。验收者可以复用同版本的可信测试记录，但必须说明复用项及依据，不能仅凭施工总结签收。根据真实风险运行必要验证；UI 行为需对应操作证据，fake 不替代真实集成。记录实际版本、命令/操作、预期与结果；环境缺口如实列出。
4. **范围内返修**：未通过时，验收者提供复现、预期/实际、受影响验收项和最小返修要求；施工者在同一授权范围内修复，交接后由独立验收者复验受影响部分及必要回归，无需让用户逐轮传话。已通过且未受影响的证据可复用。
5. **停止或交付**：全部必选标准满足才能通过。遇到同核心缺陷再次失败按上方诊断规则暂停重试；没有新证据或新方案不得继续同类尝试。扩大范围、改变验收标准、增加已限定预算、需要新增授权或不可逆操作时，把具体取舍交用户。环境缺失先完成可独立推进的部分，不把升级模型当作缺失权限/环境的解决方法。
6. **记录与汇报**：更新既有任务/状态/验收记录或本次简短记录，分别给出局部缺陷和整个任务/批次的结论。给下一步建议；未获授权的新批次不自动启动。Git 提交、推送、发布和外部写入仅按项目配置及有效授权执行，通用 skill 不默认开启。

对交付任务，最终结果须包含施工状态与独立验收状态。调用失败或外部阻塞导致阶段未执行时明确标注“未执行”，可以交付失败/阻塞说明，不得伪造阶段完成。

## 结论与用户输出

- **通过**：当前范围全部必选标准有对应证据；若用户必须确认的视觉或业务标准仍待确认，只能报告技术部分通过，整体待确认。
- **未通过**：已观察到不满足标准的交付行为。即使还有未测项，也保留已确认失败，不能用阻塞掩盖。
- **阻塞待验证**：尚无已确认失败，但缺环境、权限、必要证据或用户判断，无法完成验收。说明已完成部分及解除条件。

执行任务的最终汇报保持简短，包含：结果与范围；完成内容；规划/施工/验收的实际角色模型及评分依据；版本和验证证据（区分实测、复用、未测）；通过后的下一步建议，或失败原因和返修建议；需要用户决策的事项，没有则写“无”。不以施工自查代替独立验收，不以局部通过代替批次通过。只读检查报告配置与适用的暂定评分，明确没有实际派发；普通咨询仅回答问题，不强制列评分或未执行的角色。

## 只读预检

读取当前阶段、最新任务与验收证据、阻塞和预算；核对证据版本与当前交付是否一致。Git 项目检查分支、HEAD、已暂存/未暂存/未跟踪修改；需要核对远端时使用只读查询，未查询成功写“远端未验证”，不能用缓存断言同步或其他设备无改动。非 Git 项目说明不适用即可。

检查可见角色配置及工具能力，不用真实派发探测。规则冲突或记录缺失时并列来源与受影响步骤，继续不依赖缺口的检查。汇报版本/同步情况、当前阶段、上轮局部与整体结果、剩余问题、下一步与暂定评分模式、能否执行及待决策项；检查后停止。

## 验证本 skill

维护或验收本 skill 时使用 [验证场景](references/validation.md)。静态检查、情景推演和真实多 Agent 执行分别报告；前两者不证明模型实际调用或端到端闭环成功。
