# Agent Router

面向 Codex 用户的多 Agent 协作 skill：按当前任务评分，组织规划、施工、独立验收和范围内返修，让用户主要负责目标、业务取舍和关键结果确认。

适用于新项目和已有项目，不依赖固定的项目名称、目录结构或状态文件。它是一套供 Agent 执行的协作指令，不是独立运行的调度服务，也不会安装模型或授予模型访问权限。

## 功能

- **状态检查与恢复进度**：只读检查当前阶段、任务证据、未完成项和可用能力，给出下一步建议。
- **按批次选择协作模式**：按需求明确度、模块耦合度、变更风险和历史失败评分，每项 0–2 分，并给出依据。
- **完整交付闭环**：先制定验收标准，施工者实现并自查，另一个 Agent 实例独立验收；范围内缺陷自动返修和复验。
- **明确结果**：通过时给出证据和下一步建议；未通过时说明原因和返修建议；缺少环境或必要证据时报告阻塞。
- **可替换模型映射**：默认提供下表预设，允许项目配置其他实际可调用的模型及供应商。

| 总分 / 模式 | 规划与验收标准 | 施工 | 独立验收 |
|---|---|---|---|
| 0–1 / A 轻量 | Astra | Luna High | Sol High |
| 2–4 / A 标准 | Astra | Terra High | Sol High |
| 5–8 / B | Astra | Sol High | Astra |

默认标识分别为 `gpt-6-astra`、`gpt-6-luna`、`gpt-6.1-terra` 和 `gpt-6.1-sol`。Astra 默认 Medium，其余角色默认 High。这些是本 skill 的预设，不代表所有 Codex 用户都拥有这些模型或相同调用能力。

3–4 分先由 Sol 审计划；重大安全、数据完整性、权限或兼容风险直接采用 B；核心需求不明确时先澄清；同一核心缺陷修复后再次失败时先诊断，不盲目重试。完整规则以 [SKILL.md](skills/agent-router/SKILL.md) 为准。

## 使用前提

需要能加载本地 skills 的 Codex 环境。完整执行模式还需要宿主支持子 Agent、指定模型及相应推理参数，并具备任务所需的文件和验证工具权限。

模型不可调用时，skill 会报告具体受阻角色，不会静默换模型或用提示词扮演目标模型。状态检查和普通咨询不要求真实派发 Agent。

## 安装

### 方法一：让 Codex 安装

在带有 `skill-installer` 的 Codex 中发送：

```text
使用 skill-installer，从下面的 GitHub 路径安装 agent-router：
https://github.com/a805930382123-yper/agent-router-/tree/main/skills/agent-router
```

安装完成后，在下一轮对话中调用 `$agent-router`。如果目标位置已经存在同名 skill，安装器会停止；先检查现有版本和个人改动，再明确选择更新，不要直接覆盖自己的配置。

### 方法二：手动复制

下载仓库 ZIP 或克隆：

```shell
git clone https://github.com/a805930382123-yper/agent-router-.git
```

将仓库中的 **`skills/agent-router` 整个文件夹**复制到 `$CODEX_HOME/skills/agent-router`。未自定义 `CODEX_HOME` 时，默认位置为：

- Windows：`%USERPROFILE%\.codex\skills\agent-router`
- macOS / Linux：`~/.codex/skills/agent-router`

最终目录应为：

```text
agent-router/
├── SKILL.md
└── references/
    ├── roles.md
    └── validation.md
```

不要只复制 `SKILL.md`，也不要把仓库根目录当成 skill 目录。项目单独管理 skill 时，可采用项目已有的 `.agents/skills/agent-router` 布局，并确认当前宿主能发现该位置。

## 如何使用

### 只读检查现有项目

```text
使用 $agent-router 检查当前项目状态，给出当前任务评分、协作模式建议及依据。
只读检查，不修改文件、不派发施工、不提交或推送。
```

应得到当前阶段、上轮局部与整体结果、阻塞、下一步建议和能力核查。它不会为了检查配置而启动子 Agent。

### 执行一个明确任务

```text
使用 $agent-router 完成当前项目的以下任务：
目标：……
范围：……
验收要求：……
排除事项：……
允许规划、施工、必要本地验证、独立验收及范围内返修。
完成后给出验收结论、证据和下一步建议；不要自动启动下一批。
```

新项目不必先创建一套流程文档。Agent 会复用项目已有记录；没有时，在已授权执行中建立最少必要的任务记录，简单任务也可在聊天中记录。

### 替换角色模型

在项目协作文档中记录所需角色及模型映射，并明确让 Agent 使用该配置。每项需包含角色键、供应商/执行工具、真实模型标识、推理参数、必要能力和验证状态；不支持推理强度参数的模型标为“不适用”。

角色键和默认参数见 [角色配置](skills/agent-router/references/roles.md)。例如，可以将 `builder_standard` 映射到用户已接入的另一模型，但必须有当前环境真实可调用的工具。仅修改模型名称不会建立连接，也不保证模型能力等价。

## 你会收到什么

执行任务的最终交付包括：

1. 当前范围的通过、未通过或阻塞结论。
2. 实际完成内容、评分依据及各阶段实际 Agent / 模型。
3. 所验版本、实际验证结果、复用证据和未测项。
4. 成功后的下一步建议，或失败原因及具体返修建议。
5. 需要用户决定的事项；没有则写“无”。

施工者不能给自己的工作签验收通过；局部缺陷关闭不能代替整个任务通过。需要用户判断的视觉偏好或业务取舍未确认时，应保留待确认状态。

## 如何检查是否有效

先执行上面的只读检查示例，确认没有创建施工 Agent 或修改文件。再在可丢弃的测试目录中发送：

```text
使用 $agent-router 实现一个函数：去掉字符串首尾空白后，将十进制非负整数
字符串转为整数，拒绝空串、小数和负数。
允许规划、施工、独立验收及范围内返修。仅操作本测试目录，不提交、推送或部署。
```

检查是否先制定标准、提供评分依据、实际调用配置中的模型、使用不同施工和验收实例，并给出对应产物版本的验证证据。还可以只做情景推演，检查重大风险、重复失败和模型不可用时的处理。更多用例见 [验证清单](skills/agent-router/references/validation.md)。

**发布时的验证状态**：结构校验、相对引用检查及三份源副本一致性检查通过；独立 Agent 已走查 10 个情景并修订发现的文字歧义。尚未完成真实多模型端到端试跑，也未验证其他用户环境。情景推演不能代替实际调用和交付验收。

## 项目权限与更新

项目自己的授权、数据边界和预算继续有效。安装 skill 不授权提交、推送、发布或向外部服务发送项目内容；这些操作按用户和项目规则执行。未授权的新批次不会自动启动。

更新时先拉取仓库最新内容，比较本地自定义，再更新整个 `skills/agent-router` 文件夹。项目已有旧调度规则时，应明确新旧规则的适用范围，保留历史执行和验收记录。模型映射优先放在项目协作文档，减少更新 skill 时的冲突。
